# 多设备同步与 AI 助手（v0.12.1）

## WebDAV 配置

1. 在 WebDAV 服务中先创建专用目录，例如坚果云中的 `SmartNote`。
2. 在 SmartNote 打开工作区，进入「设置 → WebDAV 同步」。填写目录地址，例如 `https://dav.jianguoyun.com/dav/SmartNote`、用户名和应用专用密码。
3. 选择双向同步或只上传备份，设置同步间隔，勾选启用并保存。点击测试连接，确认服务支持安全的条件写入；点击立即同步。
4. 另一台设备打开一个本地工作区，填写**相同的远端目录地址和工作区同步标识**，单独填写凭据。推荐首次加入使用空目录。两台设备的本地工作区 ID、目录位置可以不同。
5. 程序运行期间，启动、周期和保存后会在后台同步；失败后约30秒重试。顶部云图标显示状态，点击可打开同步设置。退出软件后不继续后台同步。

工作区同步标识用于选中同一个远端数据集；不要给不同工作区使用同一个标识。更改远端地址、账号、模式或同步标识会重新建立基线，已有双方内容按首次同步比较。更改服务地址或账号后需要重新填写密码。

双向模式会交换新增、修改和删除。只上传备份模式不从远端自动更新本地工作副本，也不传播本地删除，远端有独立修改时仍保留冲突供处理。它不是无限版本的历史备份替代品。

### 数据范围与格式

同步工作区内的可见普通文件（笔记和资源），以及独立附件、附件清单、任务元数据、书签、人工关系、图谱布局、任务提醒配置、归档规则与分类样本配置。文件所在目录随文件创建；当前不单独同步空目录。隐藏文件、隐藏目录和符号链接不参与同步，因此回收站不会上传。

不上传 SQLite 索引、Embedding 模型/向量、缓存、设备的工作区绝对路径、应用布局、同步密码或模型 API Key。新设备会重建本地索引；凭据需要各自配置。

远端格式为 `<专用目录>/<同步标识>/workspace.json` 和 `objects/<SHA-256>`。清单记录逻辑路径、内容哈希和删除墓碑；对象不可变。该格式用于 SmartNote 设备间交换，不是可直接浏览编辑的 Markdown 目录镜像。需要普通 Markdown 文件时使用标准导出。

同步采用本地、远端和上次成功基线进行比较，不依赖文件时间。清单以强 ETag 和 `If-Match` / `If-None-Match` 条件提交；不支持条件请求的服务会明确拒绝。对象先上传、清单后提交，即使网络失败也不会将不完整文件发布为最新版本。

当前限制：每文件100MB、活动文件总量2GB、最多20000个活动文件；远端清单最多100000条记录、16MB。删除墓碑和历史对象不自动清理，以避免长期离线设备恢复已删除文件。首次和周期检查仍需扫描本地内容，尚无大规模性能验收结论。

### 冲突处理

两端同时修改，或一端删除、另一端修改时，不自动覆盖任何一方。在同步设置的「待处理冲突」中打开比较，选择保留本地、使用远端；Markdown 可手动合并。选择删除的一方表示接受该删除。

一端移动、另一端编辑同一稳定 ID 笔记时，会比较旧路径上的本地编辑和新路径上的远端版本。选择远端/合并采用新路径；保留本地恢复原路径。并发新增不同 ID 的附件会合并附件清单；同 ID 附件元数据不一致则保留冲突。

处理结果在下次同步发布。处理前本地继续编辑会使旧预览失效，需要先重新同步。已处理的冲突双方副本仍保留在应用数据 `workspaces/<本地ID>/sync/conflicts/`。

下载与删除前会保留恢复副本及日志，位于 `workspaces/<本地ID>/sync/operations/`。中断的本地提交下次启动回滚；恢复遇到后续外部修改会保留文件和备份，并提示人工处理。

## 可选大模型

「设置 → 大模型配置」中主动启用，选择：

- **OpenAI 兼容接口**：填写服务基础地址（例如 `https://api.openai.com/v1`）、实际可用的模型名称和 API Key。程序调用基础地址下的 `/chat/completions`；仅填域名时自动补齐 `/v1/chat/completions`，也可填写完整接口地址。
- **本机 Ollama**：自行准备 Ollama 和模型，填写 `http://127.0.0.1:11434` 与模型名称，例如 `qwen2.5:7b`。程序调用 `/api/chat`。此可选功能与程序自带的 BGE 离线检索模型独立。

远程地址要求 HTTPS；Ollama 限定本机回环地址。密码/Key 保存在操作系统安全凭据存储中，留空保存保留旧值，可显式清除；更改服务地址或类型不会转发旧 Key。点击「测试连接」即可使用当前填写的配置测试，无需先保存或启用；只发送一条测试消息，不保存设置、密钥或启用状态。地址或类型发生变化时测试也不会沿用原服务密钥。要使用 AI 聊天，请勾选启用并保存。

### 多供应商与模型

每个供应商有独立名称、服务类型、地址和安全凭据，最多20个。点击「添加供应商」填写配置；已有凭据的供应商进入设置时会自动拉取一次，也可使用「拉取模型」从 OpenAI 兼容的 `/models` 或 Ollama 的 `/api/tags` 获取列表。勾选表示只启用选中模型；不勾选表示全部可用。服务不支持列表或未列出私有模型时，可手动输入模型 ID。设置默认模型、默认供应商并保存；移除供应商保存后才生效。

旧版单供应商配置及密钥首次成功保存时迁移到多供应商配置。先暂存新版本凭据，再提交配置；失败不丢失旧配置。各供应商的密钥互相隔离，更换地址或协议不会带上旧服务密钥。大模型配置和密钥不参与工作区同步。

### 思考强度

默认选择「模型默认」，不传思考参数。设置页与聊天栏根据当前具体模型展示档位，切换时保留仍受支持的档位；不兼容的旧值自动回到模型默认。不支持可调思考的已知模型只显示模型默认。旧版本保存的不兼容默认值在读取时同样按模型默认处理，不改写磁盘配置或凭据版本。

| 模型 | 思考强度（均另有模型默认） |
| --- | --- |
| GPT-5 | minimal / low / medium / high |
| GPT-5.1 | none / low / medium / high |
| GPT-5.2、GPT-5.4（含 mini/nano）、GPT-5.5 | none / low / medium / high / xhigh |
| GPT-5.6（含 Sol）、GPT-6 Sol / Luna | none / low / medium / high / xhigh / max |
| GPT-6 Astra、GPT-6.1 Sol | low / medium / high / xhigh / max |
| GPT-4.1、GPT-4o 等已知普通模型 | 仅模型默认 |
| 本机 Ollama | 优先读取该模型 `/api/show` 的 `thinking.values`，支持布尔开关及模型自定义名称 |

OpenAI 兼容服务的 `/models` 没有统一的思考能力字段，因此只匹配已核对的完整模型名称及日期快照，不根据任意自定义后缀猜测能力。未知模型/第三方别名提供单独标明的「兼容档位 · 需供应商支持」，默认不传参数。兼容网关可能自行调整支持范围，以其文档和实际返回为准；软件不会通过试生成来探测能力，也不会静默重试降档。

Ollama 元数据读取不生成文本；读取期间保留当前选择，暂停发送/保存，防止把尚未验证的档位带入请求。切换模型会忽略迟到的旧查询；无元数据或读取失败时说明原因，回退到已知模型规则或兼容档位。`thinking.values: [false]` 表示不支持思考，`[true]` 表示只允许开启；其余布尔值和字符串按模型实际支持项展示。新旧服务地址之间不复用密钥。模型能力规则由前后端共享同一份 JSON。

OpenAI 兼容服务使用 `reasoning_effort`，Ollama 使用 `think`（布尔或模型档位字符串）；连接测试、聊天、审阅继续修改及旧生成入口使用对应设置。显式指定 OpenAI 档位时，使用 `max_completion_tokens=16384` 限制思考与正文总量，默认模式保留 `max_tokens=4096`。强度通常影响耗时和用量。

本次适配的是思考参数选项。应用仍使用 Chat Completions / Ollama Chat；官方 GPT-6 Luna / Sol 的 Chat Completions 工具调用只支持 `none`，GPT-6 Astra / GPT-6.1 Sol 需要 Responses API 才能调用工具，兼容网关可能不同。此限制与档位支持是两回事，不会因为展示了高档位而自动获得工具支持。

能力依据（2026-10-21 核对）：[OpenAI 思考参数](https://developers.openai.com/api/docs/guides/reasoning)、[GPT-5](https://developers.openai.com/api/docs/models/gpt-5)、[GPT-5.1](https://developers.openai.com/api/docs/models/gpt-5.1)、[GPT-5.2](https://developers.openai.com/api/docs/models/gpt-5.2)、[GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4)、[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[GPT-5.4 nano](https://developers.openai.com/api/docs/models/gpt-5.4-nano)、[GPT-5.5](https://developers.openai.com/api/docs/models/gpt-5.5)、[GPT-5.6](https://developers.openai.com/api/docs/models/gpt-5.6)、[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)、[GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)、[GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[Ollama 模型思考元数据](https://docs.ollama.com/capabilities/thinking)。

接口依据：[OpenAI Docs Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Ollama Chat](https://docs.ollama.com/api/chat)。

### 连接故障

返回 HTML 网页通常意味着填写了网站地址或错误接口路径；新版会明确提示，根地址自动补齐 `/v1`。完整接口地址不会重复拼接。不兼容的事件流、无效 JSON、服务错误、缺少 choices 或无正文分别提示，不显示服务原始响应及密钥。当前使用 Chat Completions / Ollama Chat，不支持仅提供 Responses 或 Anthropic Messages 协议的服务。

### 右侧 AI 助手

右侧栏顶部有「大纲」「AI 聊天」「关联」三个页签，每个页签使用完整侧栏空间。点击「AI 聊天」页签进入对话；使用「大纲」页签或对话内关闭按钮返回大纲。切换页签保留聊天记录、输入草稿、模型选择及侧栏宽度，生成中的回答会继续完成。页签支持左右方向键、Home、End 切换，当前编辑/分屏/预览模式保持不变。侧栏边界可拖动调宽，宽度自动保存；右上角关闭可隐藏整个侧栏，从顶部「面板」菜单恢复，隐藏时停止生成。

底部输入区提供一个「供应商与模型」下拉框，按供应商分组列出启用的模型，可输入供应商名称或模型名筛选；选择后显示「供应商 / 模型」。同名模型通过供应商身份区分。切换供应商会使用该服务配置的默认思考强度。笔记范围和思考强度使用同样的主题下拉样式，对话区顶部支持新建对话和打开大模型配置。

对话栏可切换供应商、模型和思考强度。主动发送才会调用模型；发送内容包括本次对话历史、当前笔记正文（最多18000字）、所选文本和按需检索/读取的片段。切换供应商后继续发送会把本次对话历史交给新选择的服务。当前对话只在本次运行内存中保存，关闭后再次展开会保留；新建对话或切换工作区会清空。可随时停止生成，迟到的结果不会重新出现。

「仅当前笔记」只允许读取这一篇；「工作区」可按需调用真实的语义+关键词检索和读取工具。回答列出真实来源按钮，可点击回到对应笔记位置。可询问“检索并汇总与某项目有关的笔记”，也可要求润色/整理内容。

需要改笔记时，模型通过 `propose_note_edit` 提出精确段落替换建议；点击「查看差异并确认」查看红色删除/绿色新增，点击「确认修改笔记」才写入。笔记已编辑、删除、切换工作区或建议被篡改时拒绝覆盖。保留 YAML 身份元数据，沿用普通保存的待办重新计算。每次最多5篇建议、每篇一项；不提供终端、任意文件、删除或任意网络工具。

审阅窗口中的「修改后的内容」可直接编辑，差异随编辑更新。「返回聊天」不保存笔记，再次打开同一建议保留手动草稿。在「继续提出修改意见」输入要求并点击「继续修改」，会将意见和当前草稿交给当前模型，再显示回复及新建议；可以反复调整，只有最终点击「确认修改笔记」才保存。模型未生成新建议、请求失败或停止时保留现有草稿。长草稿反馈上下文中原段落和草稿各截取前10000字，并明确标记截断；模型仍可按授权读取笔记。会话仅在本次运行中保留。确认按钮固定在窗口底部，内容区域可滚动，窗口仍可调大小。

总结当前笔记时直接使用已发送的正文。工作区检索允许一轮返回多个工具调用，不再因超过4个而中断。相同工具参数在本次请求中只执行一次；最多6轮工具交互、24次不同参数的工具尝试。达到预算后为剩余调用返回未执行说明，再进行一次不提供工具的最终回答请求，根据已有资料作答。授权范围、来源上限、修改确认和取消机制继续生效。若供应商仍返回工具而不遵循最终回答要求，会明确提示更换模型或重试。

模型需支持 Chat Completions / Ollama Chat 的工具调用协议；不支持时请更换模型。内容质量与是否正确使用工具取决于供应商及模型，建议结合来源和差异核对。

### 结构整理

检索引用摘要使用默认供应商。选择搜索结果并主动生成后，在预览窗口核对带来源的摘要；不会自动写回笔记。「润色」和「Markdown 结构整理」独立入口已移除，文字修改可直接通过 AI 聊天提出并审阅确认。

### 检索引用摘要

语义搜索得到结果后，点击「生成引用摘要」。只发送本次问题和前8条真实结果的命中片段，每条最多1800字。请求前展示来源列表，响应须带有效的 `[1]` 等编号；界面列出对应来源，可点击回到笔记指定行。摘要可复制，不自动写入正文。

来源编号校验能阻止不存在的编号，不能保证模型的每个表述都正确；请结合来源核对。生成超时为120秒，可手动取消。关闭大模型不会影响编辑、检索、归档、任务或同步。

同步和大模型操作已加入命令面板与快捷键设置，默认不占用现有组合，可自行绑定。

## v0.11.4 兼容调整

DeepSeek flash/pro 模型使用独立参数格式：不思考使用 `thinking: {type: disabled}`，指定 low/high/max 使用 `thinking: {type: enabled}` 和 `reasoning_effort`，预算使用 `max_tokens`；默认档不强制思考参数。识别供应商路由前缀但完整模型ID原样发给网关。模型名称别名不等于厂商能力保证，代理支持以实际服务为准。已知 OpenAI 推理模型继续使用 `max_completion_tokens`，其他兼容模型使用 `max_tokens`。依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode)、[Chat Completion 参数](https://api-docs.deepseek.com/api/create-chat-completion)（2026-10-21核对）。

HTTP 400 可从结构化错误中识别已知参数并给出建议；不展示服务返回的原始 message，以免错误响应反射密钥或笔记内容。DeepSeek 工具循环保留返回的 reasoning_content，普通历史助手消息补空的 reasoning_content，不修改原历史对象。本次使用隔离模拟接口验证，未访问用户配置的真实模型网关，因此截图中400的真实服务端原因尚未直接证实。

导航栏查询仅匹配文件名和去掉YAML后的正文，不请求 embedding，不触发自动保存。正文命中展示约64字以内的短片段和安全文本高亮，点击跳转命中行；保留目录层级、跨工作区加载与当前未保存草稿匹配。全局搜索页和语义检索功能保持现有能力。

## v0.12.0 长期知识库助手

AI 随请求了解软件现有功能、真实工作区范围、本地日期和自定义快捷键，并按需查询目录/笔记、待办（包含循环日期和完成记录）、书签、知识关联及附件元数据。长笔记支持分段读取；保留出处并校验历史引用，不把失效来源当作最新笔记事实。助手不会执行终端、访问其他工作区、读取密钥，或把仅有元数据的附件声称为已读正文；笔记修改仍须审阅确认。

右侧 AI 聊天新增“聊天历史”和“长期背景”入口。聊天按工作区自动保存到本机，可继续、查找和删除；重新打开助手恢复最近对话。历史修改建议不直接恢复为可应用操作。长期背景可编辑、清空，用于项目背景、术语和回答偏好，保存后随下一次主动提问发送给所选供应商。历史不自动挖掘为永久事实；长对话保留本地全文，请求使用近期上下文，旧资料可重新检索。

数据位于应用数据目录的 `workspaces/<工作区ID>/assistant-memory.json` 和 `assistant/conversations/`。历史和长期背景随原生 ZIP 备份导出恢复，普通 Markdown 导出不包含聊天；本轮尚未纳入 WebDAV 自动同步。使用举例见 [知识库助手说明](assistant-knowledge-guide.md)。

助手也能按关键词检索以前的交流，用对话标题和更新时间说明出处；不会把历史回复直接当成最新笔记事实。一次最多返回6条片段，覆盖最近200个对话且读取总量最多16MiB。

发布验证：全量 Go 测试、vet、前端类型检查和生产构建通过。模拟 OpenAI 兼容/Ollama 请求验证软件说明、工作区背景、分段读取、范围限制及历史引用重映射；元数据查询覆盖目录分页、书签、入链、附件 URL 排除、待办确认与循环日期。验证本地持久化、版本冲突防护、跨工作区隔离及原生备份恢复。浏览器回归通过历史继续/删除、长期背景保存/清空、最后选中对话恢复、保存失败保留、长对话预算与容量保护、无自动模型请求、明暗主题以及既有 AI/同步功能。最终程序隔离启动、安装卸载、内置 CPU 推理和用户数据保留验证通过。未调用用户真实模型服务；校验值见 `release-v0.12.0-sha256.json`。
